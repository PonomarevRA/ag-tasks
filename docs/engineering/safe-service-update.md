# Обновление сервиса без прерывания внешних аренд

Исполнение модели и инструментов принадлежит внешнему агенту. Замена HTTP-владельца ag-tasks не означает остановку этого агента. При открытии существующей БД миграция сохраняет `running`-сессии, их ID, роль, ключ, статус карточки, уже записанное время и исходный `lease_expires_at`. Сервис не создаёт новую аренду и не продлевает старую за агента.

## Восстановление

- До первого подтверждения новый процесс проверяет исходный UTC-срок. На точной границе срок уже истёк. Простое чтение или повтор `work/start` с прежним ключом не продлевает аренду.
- Первый принятый heartbeat с исходными полными credentials продлевает ещё действующую аренду, сохраняя записанное время. Неизвестный интервал между владельцами даёт 0 мс. Новая монотонная точка отсчёта публикуется после COMMIT под тем же lock; rollback не оставляет действующий anchor.
- Последующие heartbeat/stop считают новые ограниченные интервалы. Stop, pause или result, пришедшие первыми после restart, закрывают исходную сессию с уже записанным временем и без неизвестного интервала.
- Если аренда истекла, обычная проверка материализует `expired`. Повторный heartbeat отвергается; прежний start-key не создаёт другую сессию. Новая работа требует явного нового start-key после текущих проверок готовности.
- Runtime-owned попытки и процессы имеют отдельное восстановление/quarantine. Этот контракт не объявляет их исполняющимися после потери владельца.

Сохранённая действующая аренда подтверждает объявленную работу с карточкой, а не активность внешней модели. Точное распределение учтённого времени по календарю остаётся существующей проекцией от начала сессии; отдельного журнала каждого интервала этот выпуск не добавляет.

## Клиент и доступность

MCP stdio-процесс перечитывает `endpoint.json` перед каждой операцией и проверяет identity текущего HTTP-владельца. Без discovery он возвращает `tasks_unavailable`; перехода к произвольному сервису на историческом порту 8895 нет. Явно настроенный origin остаётся самостоятельным явным способом подключения.

Новый `--agent-console` сохраняет свои credentials при `tasks_unavailable` и повторяет только штатный heartbeat через 25 с. Он не воспроизводит автоматически изменяющие команды, не запускает работу заново и не продлевает аренду локально. Ответ `work_session_unavailable`, отказ определения или другой постоянный отказ остаётся окончательным. EOF/idle по-прежнему останавливают только собственную работу. Старый уже запущенный console/MCP-процесс не получает новый Python-код от замены приложения; новый клиент нужно подключить к обновлённому исполняемому файлу.

Непрерывная доступность HTTP не гарантируется. Если downtime вместе с задержкой следующего подтверждения превышает остаток 90-секундной аренды, она честно истекает. Это ограничение защищает от вечных фиктивных сессий.

## Порядок локального обновления

1. Собрать и проверить подпись кандидата до остановки сервиса. Данные, discovery и настройки остаются вне bundle. Сохранить прежнюю сборку для отката.
2. Проверить, что новый кандидат действительно содержит этот контракт. Старую сборку с безусловным `work_interrupted` нельзя использовать для восстановления чужих действующих аренд.
3. Заменить владельца с коротким ограниченным drain. Не останавливать внешние агенты, не отправлять pause/start от их имени и не менять их записи вручную.
4. Дождаться нового discovery, проверить application/instance identity и подтверждённый heartbeat исходных клиентов. Сравнить исходные sessionID, определение, сохранённое время и audit. При временной недоступности повторять только безопасную подтверждающую операцию.
5. При откате на старый бинарник с прежней политикой сначала дождаться отсутствия активных чужих аренд либо согласовать их прерывание. Хранение данных и подпись сами по себе не доказывают совместимость восстановления.

## Воспроизводимая проверка

`tests/test_service_update.py` запускает изолированный loopback-владелец с временной БД и шесть настоящих стандартных stdio MCP-клиентов. Они создают карточки, начинают и подтверждают работу через публичные инструменты. Проверяются обычное завершение владельца и SIGKILL; новый владелец получает другой порт и instanceID, а прежние stdio-процессы остаются открыты.

В обоих сценариях шесть исходных sessionID сохранены; первый подтверждённый неизвестный интервал даёт 0 мс; новых строк работы и повторных start/stop-событий нет. Повторный stop не добавляет время. Отдельные проверки охватывают отсутствие discovery без единого HTTP-запроса, identity mismatch до записи, точную границу TTL, первый stop/pause/result и rollback первого heartbeat. Console-тесты используют контролируемые 25-секундные тики для временного восстановления и окончательного отказа сервера.

```sh
PYTHONPATH=.:tests python -m pytest -q tests/test_service_update.py tests/test_execution.py tests/test_agent_console.py
```

Loopback/process-тесту требуется разрешение окружения на локальное прослушивание сокета. Он не обращается к live-профилю пользователя и не перезапускает установленное приложение. Прохождение этого теста не является свидетельством выполнения обновления установленного экземпляра.
